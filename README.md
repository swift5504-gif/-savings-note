# 貯金ノート（iPhone向けPWA）

## 使い方
1. `index.html`、`app.js`、`manifest.webmanifest`、`sw.js`、`icon.png`、`icon-512.png` を同じ公開フォルダに配置する。
2. HTTPSで公開する（例：GitHub Pages）。`file://`で直接開くだけではPWAとして正常動作しない。
3. iPhoneのSafariで公開URLを開き、共有メニューから「ホーム画面に追加」を選ぶ。
4. ホーム画面の「貯金ノート」を起動して使用する。

## GitHub Pagesで無料公開
1. GitHubで新しいPublicリポジトリ `savings-note` を作成。
2. このフォルダの6ファイルをリポジトリのルートへアップロード。
3. Settings → Pages → Build and deployment → Deploy from a branch → main / (root) → Save。
4. Pages画面に表示された公開URLをSafariで開く。

## 保存と注意点
- 支出・貯金の入力はlocalStorageに保存され、サーバーへ送信されない。
- 同じURLでもSafariとホーム画面アプリの保存領域が異なる場合がある。**実際に使うホーム画面アプリ内で記録**する。
- iPhoneの削除、Webサイトデータの消去、アプリの削除などで記録を失う可能性がある。JSONバックアップを定期的にファイルアプリへ保存する。
- iPhoneとMac間の同期は未実装。端末間共有には別途クラウド同期が必要。
- 週の支出は月曜〜日曜のうち平日（月〜金）の記録を集計する。土日の支出は履歴には残るが平日予算には含まれない。
- 毎週1,000円、毎月27日のへそくりは自動入金されない。実際に積み立てた時に入力する。

## 保存修正版 1.1

### 修正した直接原因
旧版は保存済み記録の読み込み時に、まだ初期化されていないparseDateを呼び出していました。記録が1件以上あると読み込みに失敗します。内包されていた配布版はエラー時に初期状態を表示するため、記録が消えたように見え、その後の保存で元の記録を上書きする危険がありました。日付処理の初期化を読み込みより前に移しました。

### その他の修正
- 保存が成功した場合だけ画面内部の状態を確定し、失敗後の再試行による二重登録を防止。
- 保存状態を画面に表示。壊れたデータは勝手に初期化せず、元データの書き出しと復元を可能に。
- 存在しない日付、未来日の新規登録、ID重複、復元時の金額上限違反、合計の整数精度超過を拒否。
- 別タブでの変更を検出し、古い画面からの上書きを防止。
- Service Workerを更新し、このアプリの旧キャッシュを削除。

### 差し替え手順
1. 記録が画面に残っている場合は、先に「バックアップ保存」を実行してください。
2. このフォルダのindex.html、app.js、sw.js、manifest.webmanifest、icon.png、icon-512.pngを、現在と同じ公開場所へまとめて上書きしてください。
3. 公開完了後、Safariで同じURLを開き直し、必要ならページを再読み込みしてください。画面下に「保存修正版 1.1」が表示されることを確認してください。
4. 支出100円を登録し、「保存済み」の表示を確認して、再読み込み後も履歴に残ることを確認してください。
5. ホーム画面からも開き直し、修正版の表示を確認してください。

ホーム画面アイコンの削除やSafariのWebサイトデータ削除は不要です。公開URLを変更すると元データを読めない場合があります。
この修正は既存の保存キーとデータ形式を維持しています。すでに旧版で上書きされたデータは、この修正だけでは復元できません。バックアップがあれば復元してください。

### 検証範囲
Node.js上の模擬ブラウザ環境で、記録後の再読み込み、保存失敗後の再試行、日付検証、ID重複、復元上限、整数精度、同時編集競合、破損時の復旧操作を検証済み。iPhone実機・公開先への反映は未検証です。
